## 0. 指导原则（所有设计的约束）

1. **客观性优先**：计算结果、判定规则、断语文本必须可复现、可回溯；任何改动不得引入未经文献核验的新文本或未经声明的推断。
2. **无损改进**：对「已核验内容」的改动只允许：(a) 修正转换/接线错误（恢复底本原字属于此类）；(b) 增加依据展示（不改变判定）；(c) 增加标注。
3. **解读层默认关闭**：任何新增解读（紫微白话层、综合报告）均为「检索式拼装」，逐条附出处与「经验规则」标签，配置开关默认关闭。
4. **确定性**：同一输入同一输出；不引入任何生成式内容到工具正式输出。
5. **UI 只做表现**：动效与交互不承载信息；纯 Markdown 回退始终可读。

## 2. P1 修复设计

### F1　调候用神字段修复（修复自相矛盾）

**现状**：`yongshen.tiaohou()` 的机器字段 `yong_wuxing` 来自月令简化规则 `_tiaohou_wuxing(mz)`（与日主无关），与同节引用的《穷通宝鉴》逐月原文提炼（`XTIQUAN`）脱钩，甚至相反（正月丁：原文庚金 vs 字段火）。

**方案**：
1. 新增映射 `GAN_WUXING = {甲:木, 乙:木, 丙:火, 丁:火, 戊:土, 己:土, 庚:金, 辛:金, 壬:水, 癸:水}`；
2. `tiaohou()` 改为：
   ```python
   gan = tiquan.get("gan", "")
   y.yong_wuxing = 去重排序([GAN_WUXING[g] for g in gan])   # 由原文提炼映射
   ```
3. `_tiaohou_wuxing` 降级为「月令寒暖提示（月令派简化规则）」：仅在 `XTIQUAN` 无 gan 时作为 fallback 填充字段，且结论中明确标注「该月原文无明确取用句，以下为月令寒暖简化提示，非原文结论」；
4. `tiaohou_text.py` 的 XTIQUAN 数据与原文不动（保持逐字底本）；
5. 结论条目顺序调整为：原文 → 喜用提炼（gan+五行） → 月令提示（若 fallback）→ 出处。

**影响面**：`bazi/yongshen.py`、`tests/test_yongshen*.py`。
**验收**：合成示例盘（丁日寅月·午时，测试用 1987-02-07，合成数据）tiaohou 输出「用神五行：金」；回归用例锁定「正月丁→金」「五月辛→土水」（己壬）等；fallback 标注用例（无 gan 月）1 个。
**客观性声明**：字段与所引原文对齐，消除机器结论与文献的矛盾；不新增文本。

### F2　格局补全：比肩/劫财（建禄·月劫·羊刃）三小类

**确认回答**：是，比肩/劫财规则缺失——`rules` 字典无键，且建禄特判仅覆盖「月干本身为比劫」一种情形。按《子平真诠》格局体系，缺口实为三小类：

| 小类 | 判定条件（月支与日主关系） | 喜用 | 章目 |
|---|---|---|---|
| 建禄格 | 月支=日主之禄（甲寅/乙卯/丙巳/丁午/戊巳/己午/庚申/辛酉/壬亥/癸子） | 财、官 | 论建禄月劫 |
| 月劫格 | 月支藏干之比劫透天干（非月干） | 财、官（与建禄同格） | 论建禄月劫 |
| 羊刃格 | 阳干月支=刃地（甲卯/丙午/戊午/庚酉/壬子） | 官杀（制刃） | 论阳刃 |

**方案**（重构 `yongshen.geju()`）：
1. 先判定月支类别：
   ```python
   LU = {"甲":"寅","乙":"卯","丙":"巳","丁":"午","戊":"巳","己":"午",
         "庚":"申","辛":"酉","壬":"亥","癸":"子"}
   REN = {"甲":"卯","丙":"午","戊":"午","庚":"酉","壬":"子"}   # 阳干刃地
   ```
2. 分支优先级：羊刃格（阳干刃地，先判，因甲卯/丙午/戊午/庚酉/壬子中卯午酉子同时是阴干禄地）→ 建禄格 → 月劫格（透比劫）→ 原 rules；
3. 喜忌规则：
   - 建禄/月劫：`tip="建禄月劫同格，禄即是劫，宜以财官为用（徐乐吾评注：皆以透干支，别取财官煞食为用）"`，`yong_wuxing=[财,官]`；
   - 羊刃：`tip="刃宜官杀制之（《子平真诠》论阳刃），无制则凶"`，`yong_wuxing=[官杀]`；
4. `ziping_text.py` 的「论阳刃」章：**实施阶段核验确认已存在**（含「论阳刃取运」），无需补提取，直接引用；
5. `shown` 推导重写为显式可读逻辑并加注释（现列表推导优先级易误读）；
6. 保留原「正官/七杀/财/印/食/伤」规则不动（回归锁定）。

**影响面**：`bazi/yongshen.py`、`bazi/ziping_text.py`（补章）、`tests/test_yongshen*.py`。
**验收**：合成月劫盘（丁日寅月、丙透时干，测试用 1987-02-07 午时，合成数据）输出用神=[金,水]；新增黄金用例 5 个：甲日卯月（羊刃→金）、乙日卯月（建禄→土金）、庚日酉月（羊刃→火）、丁日寅月+丙透（月劫→金水）、丁日寅月无丙透（正印格→水火，旧行为不变）。原六格用例全回归。
**客观性声明**：新规则逐条取自《子平真诠》原文章节，引文随输出展示；未核验章目先补后上。

### F3　何知章改造（判别力 + 成对呈现 + 岁运只报变化）

**现状问题**：(a) 阈值过松（本盘 8 命中 6，富贫/吉凶同现且无排序）；(b) 岁运表单调递增、常全「同原局」；(c) 展示误导（核查清单渲染成断言）。

**方案**：
1. **成对重组**：8 句按义理合并为 4 维成对条目，同维度两条件并排展示状态+依据+得分：
   - 财：富（财气通门户）/ 贫（财神不真）——同维强弱两面，天然消解「又富又贫」的观感矛盾；
   - 官：贵 / 贱；
   - 喜忌：吉（喜神辅弼）/ 凶（忌神辗转攻）；
   - 元神：寿 / 夭。
2. **阈值收紧与集中配置**（新增 `config.hezhi` 节，`research/hezhi_rules.md` 记录推导与样本统计）：
   | 句 | 新条件 |
   |---|---|
   | 富 | 财透干且财≥0.8，或月/日支藏财且财≥0.5 |
   | 贫 | 财<0.5 且 比劫>财×1.5 |
   | 贵 | 官透且官≥0.5（原 0.3） |
   | 贱 | 全局无官杀（保持） |
   | 吉 | 主用神（旺衰派之首）≥0.8 |
   | 凶 | 忌神最旺≥1.5 且透干（保持） |
   | 寿 | 印≥0.5 或身强（保持） |
   | 夭 | 身弱且印比均<0.5（保持） |
   阈值以 ≥20 个固定样本盘的命中分布校准（目标：命中数中位数 ≤4，避免「人人全中」）。
3. **岁运表只报变化**：逐大运/流年重算后，仅当命中集**变化**或关键得分**跨阈值**时列出行；无变化输出单行「各运命中集与原局一致（无跨阈值变化）」，不再重复 8 行。全量数据保留在 meta JSON（`hezhi_dayun/hezhi_liunian`）。
4. **展示**：标题改「何知章条件核查（成对呈现，非吉凶总断）」；每条件附依据字段值与出处引用（现有 HZ_LINES）。
5. **配置**：`hezhi_legacy: bool = False`（True 时输出旧格式，用于对照研究）。
6. **测试**：更新 `test_ditiansui_text.py`（存在性+成对格式）；新增判别力测试：样本集命中数分布断言、岁运表退化率基准（记录数值，防劣化）、矛盾对展示断言。

**影响面**：`bazi/ditiansui.py`、`report/markdown.py`、`config.py`、`research/hezhi_rules.md`、测试。
**验收**：合成示例盘输出 4 维成对表（财维双条件并排），岁运节仅列变化行（无变化时 1 行）；1990 测试盘仍见「新增」行；JSON 全量数据不变。
**客观性声明**：只改阈值/展示/归并，不改原文与事实输入；阈值集中可配且记录推导，保持可审计。

## 3. P2/P3 改进设计

### I1　统一时辰口径 + 工具联动（共享历法层）

   - 结果对象增 `caliber: str` 字段（「钟表时支（未校正）」/「真太阳时支（已校正 −43.5 分）」），`__str__` 输出口径行。

   - CLI 增 `fortune context` 子命令生成/读取；各工具 schema 增可选 `context` 参数：传入则复用历法字段，**一致性校验**（context 与工具参数冲突 → 明确报错，防错配）；

4. 报告：每个工具输出统一「口径声明块」（时区/夏令时/真太阳时/换日/时支两口径），位置固定。

## 4. fortune_comprehensive —— 无 LLM 的可靠方案（可行）

**结论：完全可行。** 本质是「确定性聚合引擎 + 已核验词条检索」，同输入同输出，零生成、零采样；LLM 仅允许宿主在**工具输出之外**做润色（README 明示边界）。

### 4.1 管线（7 步，全部确定性）

1. **统一归一化**：一份 NormalizedBirth 跑全部工具 → 结构化事实集 F（bazi 多流派、ziwei 两口径、称骨、梅花、小六壬、六爻(可选 date)）。
2. **用神共识矩阵**：流派×五行 0/1 投票 → 五行得票率；输出矩阵表（可复核）。tiaohou 经 F1 修复后参与；等权默认，`config.comprehensive_weights` 可配。
3. **一致性检查**：身强弱 vs 各派用神方向（身强→克泄耗、身弱→生扶）；不一致项列入「内部冲突清单」如实展示（如调候与旺衰相左）。
4. **跨工具维度映射**：定义「维度 → 触发条件」规则表（全部为结构化字段判定），例：
   - 婚恋 = 八字财/官星状态 ∧ 紫微夫妻宫大限 ∧ 六爻妻财/官鬼状态 ∧ 梅花体用；
   - 事业 = 官杀状态 ∧ 紫微官禄宫 ∧ 流年十神；……
5. **词条检索（RAG 式）**：词条库（条件表达式 + 文本 + 出处 + 「经验规则」标签）——文本**全部复用已核验内容**（各模块现有引文/断语表/research 文档），不新增未核验文本。
6. **共识度打分**：每条结论 `证据数/参与工具数` → 强共识（≥0.6）/ 中（0.3–0.6）/ 弱（<0.3）；冲突结论并列呈现，不调和。
7. **输出**：Markdown（口径声明 → 共识矩阵 → 分维度条目+证据链 → 冲突清单 → 未覆盖声明）+ JSON。

### 4.2 可靠性论证
- 无温度/采样/生成：逐条结论可回溯到（工具, 字段, 规则/词条, 出处）；
- 黄金用例 + 可复现性断言（同输入字节级一致）；
- 结论只陈述「条件→词条→出处」链，不做「你今年必发财」式断言。

### 4.3 交付物
`comprehensive/`（管线、维度规则表、词条库、共识度）、`tests/test_comprehensive.py`、`research/comprehensive_rules.md`（每条规则推导与样本统计）。

2. **流年时间轴**（§F4 已述）；

- 仅透明度/位移/高度；时长 ≤300ms；ease-out；不旋转、不缩放、不闪烁；
